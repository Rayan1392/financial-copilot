# واژه‌نامهٔ متن رابط کاربری ساپیو

هر مفهوم در رابط کاربری فقط با یک املا نوشته می‌شود تا یک چیز در دو صفحه دو جور خوانده نشود.

**منبع واحد:** فهرست واژه‌ها در [`src/frontend/src/lib/copy/fa-terminology.ts`](../src/frontend/src/lib/copy/fa-terminology.ts) است. این سند فقط آن را توضیح می‌دهد. تست [`fa-terminology.test.ts`](../src/frontend/src/lib/copy/__tests__/fa-terminology.test.ts) همهٔ فایل‌های `src/frontend/src` را می‌گردد. اگر شکل ممنوع یک واژه در متن کاربر بیاید، تست شکست می‌خورد و نام فایل و خط را می‌گوید.

## واژه‌ها

| بنویسید | ننویسید | توضیح |
|---|---|---|
| گذرواژه | رمز عبور | شکل غالب در جریان‌های پروفایل، بازیابی و تعیین گذرواژه. |
| تأیید، تأییدشده، تأیید نشده | تایید | املای مصوب فرهنگستان، با همزه. |
| جست‌وجو، جست‌وجوی | جستجو | املای مصوب، با نیم‌فاصله (U+200C). |
| تحلیل‌اپ | TahlilApp | داخل متن فارسی، نام فارسی می‌آید. نام لاتین فقط در کد، نام API و برچسب‌های تمام‌لاتین می‌ماند. |

## افزودن واژهٔ تازه

وقتی یک مفهوم در دو جای محصول دو جور نوشته شده است:

1. یک ردیف به `FA_TERMINOLOGY` اضافه کنید (`preferred`، `avoid` و `note`).
2. اولویت با املای مصوب فرهنگستان است. اگر مصوبه‌ای نباشد، شکلی را بگیرید که در برنامه بیشتر به کار رفته است.
3. تست را اجرا کنید (`npx vitest run fa-terminology`) و جاهایی را که فهرست می‌کند اصلاح کنید.
4. جدول بالا را هم به‌روز کنید.

## دامنه

- **پوشش تست:** فقط متن فرانت‌اند (`src/frontend/src`) بررسی می‌شود.
- **بک‌اند:** پیام‌های بک‌اند که به کاربر می‌رسند هم باید همین واژه‌ها را رعایت کنند. یک بار به‌صورت دستی اصلاح شده‌اند، ولی هنوز تست خودکار ندارند.
