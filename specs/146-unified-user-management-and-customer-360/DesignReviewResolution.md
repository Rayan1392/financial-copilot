## Focused verification

- **Persistence/topology:** `ServiceCollectionExtensions.cs` registers `AuthDbContext` and `BillingDbContext` with the same `FinancialCopilot` PostgreSQL connection string. The contexts retain separate EF models and migrations. `CustomerAccountRow` has a unique `(TenantId, UserId)` index and a `SubscriptionPlanCode` index; wallet projection is keyed by `CustomerAccountId`. The documents explicitly defer the three Billing filters rather than relying on an unbounded cross-context approximation.
- **Permissions:** The composed route has one explicit base permission and per-section checks. The response differentiates unavailable data from unauthorized data, and no section data is queried or returned without its existing permission.
- **Session semantics:** `RefreshTokenRow` persists `CreatedAt`, `ExpiresAt`, `RevokedAt`, and `ReplacedByTokenId`; `TokenHash` is unique. Existing refresh logic expires, rotates, and replay-revokes these rows. The new definition matches those persisted states without changing session behavior.

`OpenQuestions.md` is unchanged because the three findings are now settled design contracts and require no additional product, security, or legal decision. This remains design-only: no production code was changed, and no migrations or tests were generated, applied, or run.

## Final implementation readiness

**READY_FOR_IMPLEMENTATION** — The original major is resolved by removing the unsupported Billing directory filters from MVP, and both minor contracts are explicit. The implementation tasks retain query-plan, authorization, and refresh-session tests as verification gates.
